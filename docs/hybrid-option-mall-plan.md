# 하이브리드 옵션몰 (Hybrid Option Mall) 기획 문서

> 버전 v0.1 (초안) · 작성일 2026-06-19 · 작성 올림플래닛 옵션몰 기획/개발
> 본 문서는 내부 합의 및 클라이언트 제안을 위한 기획·설계 기준이다. 대외 공유 시 대외비 수치·고객 데이터는 제외한다.

---

## 1. 배경과 목적

옵션몰은 건설 분양 시 각 주택 타입의 옵션(option)을 고객이 직접 보면서 선택하고, 선택에 따라 견적(estimate)이 실시간으로 책정되는 셀프 견적 솔루션이다. 현재 표준 구성은 **좌측 360 VR 플레이어 + 우측 옵션/견적 패널**의 양방향 연동 구조다.

문제는 사업지 전(全) 타입을 VR 플레이어로 제작할 경우 촬영·모델링·후처리 비용(cost)이 크다는 점이다. 사업지에 따라 타입이 수십 개에 이르면 VR 제작 코스트가 솔루션 도입의 진입 장벽이 된다.

이를 해결하기 위해 **하이브리드(hybrid) 모델**을 제안한다. 한 사업지 안에서 일부 핵심 타입은 VR 플레이어로, 나머지 타입은 플레이어 없이 좌측에 썸네일 이미지(thumbnail image)만 붙는 형태로 혼합 운영한다. 우측 옵션·견적 로직은 두 모드에서 완전히 동일하게 동작한다.

### 기대 효과
- VR 제작 범위를 핵심 타입으로 한정해 사업지당 제작 코스트 절감
- 플레이어 없는 타입도 동일한 옵션 선택·견적 경험 제공
- 사업지별로 VR/이미지 비율을 유연하게 구성 → 영업 단계에서 가격·납기 옵션 다변화

---

## 2. 제품 정의와 핵심 구조

옵션몰의 화면은 두 영역으로 나뉜다.

- **좌측 비주얼 영역(Visual Area)** — 선택한 옵션의 시각적 결과를 보여준다.
- **우측 옵션/견적 영역(Option & Estimate Panel)** — 옵션을 선택하고 누적 견적을 확인한다.

표준(VR) 버전에서 두 영역은 양방향으로 연동된다.
- 우측에서 옵션 선택 → 좌측 비주얼(VR 씬 또는 이미지) 갱신 + 견적 재계산
- 좌측 비주얼의 핫스팟(hotspot) 클릭 → 우측 해당 옵션 그룹으로 포커스 이동

하이브리드의 핵심 설계 원칙은 **비주얼 영역을 교체 가능한 "뷰어 모드(Viewer Mode)"로 추상화**하는 것이다. 옵션 데이터 모델과 견적 엔진은 뷰어 모드와 무관하게 공유되고, 좌측만 모드에 따라 갈아끼운다.

---

## 3. 뷰어 모드 (Viewer Mode)

좌측 비주얼 영역은 타입별로 다음 중 하나의 모드를 가진다.

| 모드 | 좌측 구성 | 양방향 연동 | 비고 |
|------|-----------|-------------|------|
| `vr` | 360 VR 플레이어 | 핫스팟 ↔ 우측 양방향 | 제작 코스트 높음. 핵심 타입에 적용 |
| `image` | 옵션 결과 썸네일 이미지(들) | 우측 → 좌측 단방향(이미지 전환) | 이미지 슬롯만 교체. 제작 코스트 낮음 |
| `none` | 비주얼 없이 우측 패널 단독 | 연동 없음 | 자이 StyleUp형. 옵션 텍스트/가격 중심 |

> 설계상 `vr`/`image`/`none`은 동일한 인터페이스(뷰어 컴포넌트 계약)를 따르며, 타입 설정에서 `viewerMode` 값 하나로 분기한다. 이 추상화가 하이브리드의 기술적 관건이다.

첨부 레퍼런스 기준:
- ELIF(엘리프 제천 스마트시티) → `vr` 모드 (좌측 360 플레이어 + 공간 메뉴)
- 자이 StyleUp → `none`에 가까운 모드 (좌측 비주얼 없이 우측 옵션 UI 중심)

## 4. 데이터 모델 (Data Model)

옵션몰 전반에서 공유하는 도메인 구조다. 뷰어 모드와 독립적이다.

```
Project(사업지)
└─ HousingType(타입: 84A, 84B …)
   ├─ viewerMode: vr | image | none
   ├─ Space(공간: 주방, 현관, 거실 …)      ← 공간 단위 네비게이션(ELIF형)
   │  └─ OptionGroup(옵션 그룹: 주방 특화, 빌트인 오븐장 …)
   │     ├─ selectionType: single | package
   │     ├─ dependsOn: <다른 옵션 선택 조건>  ← 활성화 의존성
   │     └─ OptionItem(옵션 항목)
   │        ├─ label, description, price(델타 가격)
   │        ├─ isDefault(미선택/기본 제공 여부)
   │        ├─ badge(예: "시그니처스타일")
   │        └─ visualRef(연결된 VR 씬 / 이미지 슬롯)
   └─ Package(패키지: 스타일업 패키지)         ← 패키지 단위(자이형)
      └─ ... (OptionGroup과 동일 구조 재사용)
```

### 두 가지 옵션 구성 패턴
레퍼런스에서 관찰된 두 패턴을 모두 수용한다.

1. **공간 기반(Space-based)** — ELIF형. 좌측 공간 메뉴(주방·현관·거실·드레스룸·욕실·침실…)로 이동하며 공간별 옵션 그룹을 선택. VR/이미지 모드와 잘 맞는다.
2. **카탈로그 기반(Catalog-based)** — 자이형. "스타일업 패키지"(단일 선택)와 "개별선택"(항목별 단일 선택)으로 구성. `none` 모드와 잘 맞는다.

데이터 모델은 두 패턴을 같은 스키마로 표현하되, 화면 레이아웃 프리셋만 달리한다.

### 핵심 속성 메모
- **델타 가격(delta price)** — 옵션 가격은 기준가 대비 추가 금액으로 표기(예: `+2,850,000원`, 기본형 `0원`). 누적 합산이 총 견적이 된다.
- **의존성(dependency)** — 일부 옵션은 다른 옵션 선택 시에만 활성화된다. ELIF 레퍼런스의 *"주방 특화 [선택형2] 시그니처 옵션이 선택 시 활성화됩니다"* 가 대표 사례. (빌트인 오븐장 선택형은 주방 특화 시그니처 선택 시에만 활성)

---

## 5. 견적 로직 (Estimate Logic)

- 각 옵션 그룹은 `single`(하나만 선택) 또는 `package`(패키지 단위) 선택 규칙을 가진다.
- 기본형/미선택 항목은 `0원`이며 항상 유효한 선택지로 존재한다.
- 총 견적 = 선택된 모든 옵션의 델타 가격 합. 화면 하단에 실시간 표기(`총 견적 금액`, `총 옵션금액`).
- 의존성 위반 시 처리: 상위 옵션 해제 시 하위 의존 옵션도 자동 기본값으로 복귀(견적 재계산).
- 산출물: `견적서 확인` — 선택 내역과 합계를 정리한 견적서(estimate sheet) 생성.

> 견적 금액·할인 정책 등 사업지별 실제 단가는 대외비이므로, 본 문서에는 레퍼런스 화면에 노출된 예시 수치만 인용한다. 실데이터 연동 시 별도 관리(확인 필요).

## 6. 하이브리드 분기 정책 (Hybrid Branching Policy)

- 사업지 설정에서 타입별로 `viewerMode`를 지정한다.
- 입주민/고객 진입 시 타입 선택 → 해당 타입의 `viewerMode`에 따라 좌측 영역이 결정된다.
- 우측 옵션/견적 UX는 모든 모드에서 동일하다. (학습 비용 최소화)
- `image` 모드: 옵션 선택 시 미리 렌더링된 결과 이미지로 좌측을 교체(전/후 비교 가능하도록 슬롯 설계).
- `none` 모드: 좌측을 숨기고 우측 패널을 풀폭(full-width)으로 확장하거나, 자이형처럼 중앙 정렬 카탈로그 레이아웃 사용.

### 운영 시나리오 예시
- 84A(대표 타입) → `vr`, 84B → `image`, 59·74 등 비핵심 타입 → `none`
- 영업 단계에서 "VR 3개 타입 + 이미지 5개 타입" 식으로 패키지 견적 제시 가능

---

## 7. 핵심 인터랙션 시나리오

1. 고객이 타입(84A) 선택 → 해당 타입 `viewerMode=vr` → 좌측 360 플레이어 로드, 우측 주방 옵션 패널 표시.
2. 우측에서 "주방 특화 → 선택형2(시그니처)" 선택 → 좌측 VR 씬이 시그니처 마감으로 전환 + 하단 견적 `+8,400,000원` 반영 + 의존 옵션(빌트인 오븐장 선택형) 활성화.
3. 좌측 공간 메뉴에서 "현관"으로 이동 → 우측이 현관 옵션 그룹으로 전환.
4. (다른 타입) 84B 선택 → `viewerMode=image` → 좌측은 썸네일, 우측 동일 UX. 옵션 선택 시 이미지 교체.
5. 모든 선택 완료 → `견적서 확인` → 선택 내역·합계 견적서 출력.

## 8. 기술 아키텍처 방향 (초안 / 확인 필요)

- **프론트엔드**: 컴포넌트 기반 SPA. 좌측 `<VisualArea>`는 `viewerMode`에 따라 `<VrViewer>` / `<ImageViewer>` / `null`을 렌더하는 어댑터(adapter) 패턴.
- **상태 관리**: 옵션 선택 상태와 견적은 뷰어와 분리된 전역 스토어(store)에서 단일 소스로 관리. 좌측·우측·하단이 같은 상태를 구독.
- **데이터**: 사업지/타입/공간/옵션을 JSON 스키마로 정의 → 관리자 입력으로 사업지별 구성 생성(노코드 지향).
- **VR 연동**: 기존 360 플레이어를 뷰어 인터페이스 계약에 맞춰 래핑(wrapping).
- 스택(framework) 확정은 별도 논의 필요.

---

## 9. 단계 계획 (Phasing)

- **Phase 0** — 본 기획 문서 + 데이터 스키마 확정 (현재 단계)
- **Phase 1** — 우측 옵션/견적 엔진 + `none`/`image` 모드 동작 프로토타입 (플레이어 불필요, 빠른 검증)
- **Phase 2** — `vr` 모드 연동 및 양방향 핫스팟
- **Phase 3** — 관리자 구성 도구(사업지/타입/옵션 입력) + 견적서 출력
- **Phase 4** — QA 및 실사업지 파일럿

## 10. 열린 질문 (Open Questions)

- 좌측 비주얼 없는 `none` 모드의 표준 레이아웃을 자이형 카탈로그로 고정할지, 자체 디자인을 만들지?
- `image` 모드에서 옵션 조합별 이미지 수가 폭증할 수 있음 → 슬롯/레이어 합성으로 줄일지, 사전 렌더로 갈지?
- 견적서 출력 포맷(PDF/웹/상담원 연동)과 개인정보 취급 범위? (개인정보는 최소 수집 원칙)
- 관리자 구성 도구의 권한·운영 주체(올림플래닛 vs 건설사 vs 분양대행)?
```
